# 로드맵 형식 (docs/roadmap.md 가 따라야 하는 규칙)

`publish-roadmap` 스킬이 이 형식을 기계적으로 읽어 GitHub 마일스톤 · 이슈로 발행하고, `run-milestone` 스킬이 이슈 순서를 정한다. 형식을 바꾸면 두 스킬도 함께 고친다.

## 1. 문서 뼈대

```
# BIVE 로드맵
> 상태 줄: 버전 · 갱신일 · 기준 문서 버전
## 0. 원칙            (마일스톤 분할 기준, 우선순위 해석)
## 1. 마일스톤 요약   (표: 마일스톤 | 목표 | PRD 단계 | 이슈 수 | 상태)
## 2. 마일스톤 상세   (마일스톤마다 2.x 절)
## 3. 커버리지 표     (모든 요구사항 ID · 화면 ID)
## 4. needs-human 후보
## 5. 변경 이력
```

## 2. 마일스톤 절 (`### 2.x Mn 이름`)

각 마일스톤 절은 아래 항목을 이 순서로 가진다.

- **목표**: 한 문단.
- **완료 기준 흐름**: 번호 목록. QA 서브에이전트가 **그대로 실행**할 수 있는 시나리오(명령 · 클릭 · 기대 결과). 실행 불가능한 추상 문장 금지.
- **범위 밖**: 이 마일스톤에서 일부러 하지 않는 것.
- **이슈 표**: 아래 열을 가진 표 1개.

| 열 | 규칙 |
|---|---|
| 키 | `Mn-NN` (예 `M1-03`). 마일스톤 안에서 유일, 발행 후 변경 금지 |
| 제목 | 명사형 한 줄. GitHub 이슈 제목은 `[Mn] 제목` |
| 유형 | `feature` `bug` `chore` `docs` 중 하나 (→ `type:` 라벨) |
| 영역 | `app` `orchestrator` `store` `parser` `shared` `ci` `docs` 중 1개 이상, `·`로 구분 (→ `area:` 라벨) |
| 의존 | 먼저 끝나야 하는 키 목록, 없으면 `—`. 다른 마일스톤 키 참조 가능 |
| 수용 기준 | 검증 가능한 문장 1~4개, `·`로 구분(항목 안에서는 `·`를 쓰지 않는다. 발행 때 `·`로 나눠 체크리스트 항목을 만든다). "동작한다" 같은 모호한 문장 금지. 테스트 파일 이름 · 명령 · 화면 상태 · 오류 코드를 적는다 |
| 관련 ID | PRD ID · SCR ID · ADR 번호만, `·` 구분 (문서 절 번호 같은 다른 값은 제목에) |
| 이슈 | 발행 전 `—`, 발행 후 `#번호` (publish-roadmap이 채움) |

이슈 크기: PR 하나로 끝나는 크기(서브에이전트 1회 작업, 변경 파일 20개 이내 목표). 넘치면 쪼갠다.

## 3. 커버리지 표

| 열 | 규칙 |
|---|---|
| ID | PRD 4장 · 5장의 모든 ID와 SCR-01~21 전부. 하나라도 빠지면 pr-reviewer가 반려 |
| 종류 | `요구사항` `비기능` `화면` |
| 우선 | PRD 우선순위 (P0 · P1 · P2 · —) |
| 마일스톤 | 구현 마일스톤. 여러 단계에 걸치면 `M1(부분)·M2` |
| 이슈 키 | 해당 키 목록 |
| 비고 | `미정` 항목의 ADR 번호, 비목표 처리 사유 등 |

## 4. 발행 규칙 (publish-roadmap이 따른다)

- 마일스톤: 제목 `Mn 이름`, 설명 = 목표 + 완료 기준 흐름. 이미 있으면 재사용.
- 이슈: 제목 `[Mn] 제목`, 본문은 아래 틀. 같은 제목이 이미 있으면 만들지 않고 번호만 기록.

```
## 목표
<표의 제목을 한두 문장으로>
## 수용 기준
- [ ] ...
## 관련 ID
PRD · SCR · ADR
## 의존
#번호 (키)
## 로드맵 키
Mn-NN
```

- 라벨: `type:<유형>`, `area:<영역>`마다 1개. 라벨이 없으면 만든다.
- 발행 뒤 roadmap.md의 `이슈` 열을 `#번호`로 채우고 커밋한다.

## 5. 변경 이력

로드맵을 고칠 때마다 `## 5. 변경 이력`에 날짜 · 무엇을 · 왜 한 줄. 발행된 이슈의 수용 기준을 바꾸면 GitHub 이슈 본문도 같이 고친다.
