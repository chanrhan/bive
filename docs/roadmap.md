# BIVE 로드맵

> v1 · 2026-10-15 · 기준 문서: PRD v0.9 · 화면 정의서 v0.5 · 기획서 (docs/spec) · ADR-001~016

## 0. 원칙

- PRD 6장의 단계를 이슈 크기에 맞게 나눈다 (ADR-015). 매핑: **M0** 기반 → (PRD 없음) · **M1** 첫 슬라이스 → PRD M1 · **M2** 측정 시작 → PRD "M1 직후 측정 시작" · **M3 · M4 · M5** → PRD M2 MVP(P1 전부)를 판정 확장 / 설계 화면 · 수집 / 지시 · 질문 · 추적성으로 3분할 · **M6** 확장 → PRD M3(P2 전부).
- 우선순위 해석: P0 = M1, P1 = M3~M5(MET-01만 M2), P2 = M6. PRD가 "후보"라고 한 우선순위는 그대로 둔다.
- 모든 자동 테스트는 ScriptedAdapter(가짜 에이전트)로 돈다 (ADR-016). 실제 Claude 인증 · Windows 완주는 needs-human.
- 이슈 1개 = PR 1개. 의존 열의 키가 닫히기 전에는 시작하지 않는다.
- 화면 이슈의 수용 기준은 `docs/spec/screens.md`의 해당 SCR 절(구성 요소 · 동작 · 상태 · 이동 경로)을 Playwright 체크리스트 테스트로 검사하는 것을 포함한다.

## 2. 마일스톤 상세

### 2.0 M0 기반

**목표**: 제품 기능 없이, 세 층(앱 · 오케스트레이터 · 저장소)이 서로 연결되고 모든 검증 명령이 이 VM과 CI에서 도는 상태를 만든다.

**완료 기준 흐름**:
1. `main` 최신에서 `pnpm install --frozen-lockfile && pnpm lint && pnpm typecheck && pnpm test && pnpm build`가 전부 0으로 끝난다.
2. `pnpm e2e`가 Playwright 브라우저 모드로 렌더러를 열어 레이아웃(사이드바 · 중앙 · 오른쪽 채팅 영역 · 하단 연결 상태)이 있는지 통과한다.
3. `xvfb-run -a pnpm smoke`가 Electron 창을 띄워 제목 "BIVE"를 확인하고 종료한다.
4. `pnpm --filter @bive/orchestrator start`로 백그라운드 프로세스를 띄우고, 앱(또는 `pnpm --filter @bive/app cli ping`)이 파이프로 `ping` → `pong`을 받는다. 사이드바 하단에 "연결됨"이 보인다.
5. `fixtures/sample-next-app`에서 `pnpm test`가 HTTP 인수 테스트 1개를 통과한다.
6. GitHub Actions `ci`가 PR에서 초록이다.

**범위 밖**: 요구사항 · 규칙 · 실행 기능, 실제 SDK 호출.

### 2.1 M1 첫 슬라이스

**목표**: PRD 6장 M1. 요구사항 1개를 적으면 규칙이 제안되고, 승인하면 유형 A 파이프라인(테스트 작성 → Red → 구현 → 검사)이 돌아 판정 · 병합 · 화면 갱신까지 사람 개입 없이 끝난다. 모든 자동 검증은 ScriptedAdapter로.

**완료 기준 흐름** (기본 브랜치 최신, `BIVE_AGENT=scripted BIVE_HOME=$(mktemp -d)`):
1. `scripts/reset-fixture.sh`로 픽스처를 초기화하고, 앱(또는 `pnpm --filter @bive/app cli`)에서 **[폴더 열기]**로 픽스처 폴더를 연다 → `.bive/project.json`이 생기고 요구사항 화면(SCR-02)으로 들어간다. 같은 폴더를 다시 열면 파일을 다시 만들지 않는다.
2. 설정(SCR-21)에서 역할별 모델과 예산 한도(실행 전체 · 역할별)를 저장한다. 저장 전에는 [실행]이 "예산 · 모델 미설정"으로 거부된다.
3. SCR-02에서 **[+ 새 요구사항]** → "헬스 체크 응답에 서버 시각이 포함된다" 입력 → ⌘↵ 저장 → 카드가 생기고 생성 주체 아이콘이 사람이다 → 규칙 제안이 생성돼 알림 배지가 1이 된다.
4. 알림 아이콘 → 승인 대기(SCR-17) → 카드(종류 태그 "신규", 제목, 생성 주체 에이전트) → 상세에 제목 · EARS 진술 · 검사 종류 · 부모 요구사항 · 근거 → **[수정]**으로 제목 한 글자 고침 → **[승인]** → 처리됨 필터에서 승인 기록(수정 내용 · 주체)이 보인다. **[거절]**은 사유 없이는 닫히지 않는다.
5. SCR-03 규칙에서 승인된 규칙을 선택 → **[실행]** → 실행 시작 확인 → 실행이 생성되고 SCR-05 파이프라인 영역에 단계가 승인 → 테스트 작성 → Red 확인 → 구현 → 검사 → 화면 갱신 순으로 진행된다.
6. 끝나면 SCR-05 머리줄에 "판정 기준 main@<커밋>", 준수 카드 "1 / 1", 규칙 목록에 통과 배지(흐린 점) · 실행 링크(비용 합계 · 턴)가 보인다. 픽스처의 `git log main`에 병합 커밋이 있고 실행 브랜치가 남아 있다.
7. 실패 경로: ScriptedAdapter 시나리오 `fail-check`로 실행하면 검사 실패 → 구현 회귀 2회 → 실패 종료, 규칙 카드 2줄째에 "실패" · 상세의 테스트 출력이 자동으로 펼쳐지고 브랜치는 병합되지 않는다.
8. 끊김: 구현 단계 중 오케스트레이터 프로세스를 `kill -9` → 재기동 → 실행 상태 "중단" → SCR-05 **[재개]** → 마지막 완료 단계 다음부터 새 세션으로 끝까지 간다. 그동안 앱을 닫았다 열어도 진행 상태가 유지된다.
9. `pnpm test`의 무결성 테스트: 역할 에이전트 세션에 승인 메서드 · Bash 도구가 없고, MCP 도구가 섞이면 실행이 거부된다.

**범위 밖**: 변이 주입, 구조 · 계약 검사, 검토 대기열, 잠정 승인, 채팅, 설계 화면, 실제 SDK 완주(needs-human).

### 2.2 M2 측정 시작

**목표**: PRD "M1 직후 측정 시작". 코드 열람 횟수 · 사유를 기록하고 검증 화면에 분포를 보인다.

### 2.3 M3 판정 확장

**목표**: PRD M2의 판정 · 실행 쪽 P1. 구조 · 계약 검사와 변이 주입이 파이프라인에 들어가고, 실행 유형 B·C·D, 검토 대기열, 계약 변경 승인, 추적성 결함 · 규칙화 불가 · 변경 이력 · 유입 상한이 동작한다.

**완료 기준 흐름**:
1. 픽스처에 블록 선언(auth · lib) 추가 후 구조 검사 규칙 2개가 SCR-03에 내장 규칙으로 보이고, 선언 외 import를 넣은 픽스처 변형에서 실행하면 검사 단계가 실패 판정한다.
2. OpenAPI 파일을 계약으로 등록(SCR-04) → `contract` 검사 규칙이 연결되고 유형 B 실행이 테스트 작성 · Red 확인을 생략하고 통과한다.
3. 유형 A 실행에 변이 주입 단계가 추가돼 ScriptedAdapter `mutant-survives` 시나리오에서 변이 생존 → 검토 대기열(SCR-18)에 자동 등록 → "테스트 보강"을 고르면 유형 C 실행이 생성되고 변이 재주입으로 끝난다. "판정 격리"는 사유 없이는 닫히지 않는다.
4. 예산 초과 시나리오에서 검토 대기열에 등록되고 "한도 상향 재개"로 이어서 끝난다.
5. 계약 파일을 바꾸는 지시 대신 테스트용 RPC로 계약 변경 제안을 넣으면 SCR-19에 diff · 영향 규칙 · Breaking 수가 보이고 승인하면 유형 B 실행이 생성된다.
6. 규칙 없는 요구사항을 만들면 SCR-02 카드에 "추적성 결함", '규칙화 불가'로 표시한 요구사항은 결함에서 빠지고 SCR-05 카드에 비율이 보인다.
7. 요구사항을 편집하면 SCR-06 변경 이력(접힘)에 내용 · 시각 · 주체가 남는다.
8. 제안 41개를 넣으면 머리줄이 빨강이 되고 42번째 제안 생성이 거부된다. 설정에서 상한을 50으로 바꾸면 허용된다.
9. 코드 파일을 바꾸고 커밋하면 영향 규칙이 "재검증 필요"가 된다. 같은 커밋 3회 판정이 같다.
10. PostgreSQL 픽스처 변형에서 1~2가 통과한다.

**범위 밖**: 설계 화면, 채팅 · 지시, 잠정 승인 정책 UI.

### 2.4 M4 설계 화면 · 수집

**목표**: PRD M2의 설계 · 수집 쪽 P1. 기존 프로젝트 동기화, 파서, 수집 COL-01~04, 설계 화면 6개(아키텍처 · L0 · L1 · 흐름도 · ERD · 변경 로그)와 ADR 화면.

**완료 기준 흐름**:
1. 새 픽스처(블록 미선언)를 열어 **[BIVE 동기화]** → 블록 선언 초안이 승인 대기에 제안되고, 승인하면 SCR-08 아키텍처에 카드 6개와 L0 · L1 요약이 보인다.
2. 실행 하나를 돌린 뒤 SCR-08 머리줄에서 그 실행을 고르면 카드 값이 바뀌고, 카드를 누르면 정의 · 수치 · 파일 · 기준 실행이 펼쳐진다. 변경량 카드는 기준 실행 N개 미만이면 비교를 표시하지 않는다.
3. SCR-09 L0에서 서버 → DB 연결선을 고르면 Prisma 계약 · contract 규칙 · 최근 실행이 보이고, 계약 없는 연결은 경고 · 강조 칩에 잡힌다. SCR-10 L1에서 선언 외 의존은 빨강.
4. SCR-11 흐름도에서 `/api/health`가 블록 그룹 아래 있고 테스트 경유 호출은 실선, 정적 분석만은 점선이다. OpenAPI 미정의 엔드포인트에 "계약 미등록" 태그.
5. SCR-12 ERD에 Prisma 테이블 · 관계가 있고 명세 외 테이블은 점선 · 경고.
6. SCR-14 변경 로그에 실행의 변경 요약 · 사유 · 관련 ADR · 규범이 있고 ADR 없는 변경에 예외가 표시된다. SCR-15 ADR 목록 · 상세 · 규범 연결 없는 ADR 표시.

**범위 밖**: 지시 액션(M5), FE 내부 분석(ADR-003).

### 2.5 M5 지시 · 질문 · 추적성

**목표**: PRD M2의 상호작용 P1. 에이전트 채팅 패널, 항목 단위 질문 · 지시, 설계 화면의 지시 연결, 추적성 맵, 잠정 승인 · 대기열 설정 UI.

**완료 기준 흐름**:
1. 모든 화면 오른쪽에 채팅 패널이 있고, 창을 1000px로 줄이면 44px 띠로 접혔다가 눌러서 겹쳐 열린다.
2. SCR-03에서 규칙을 고르고 C 키 → 참조 칩 → [질문] → "이 규칙의 최근 판정은?" → ⌘Enter → 답변이 화면 사실만으로 오고 "~ 채팅" 주체가 붙는다. 참조를 지우고 선택도 없으면 전송이 비활성이다.
3. 같은 항목에 [지시] → "응답에 버전도 포함" → 제안 PRP-xxx가 생기고 스레드에 "제안 · 승인 대기" 기록 → 승인 대기에서 승인 → 요구사항 변경 + ADR + 실행 생성. 규범 변경이 없는 지시("중복 코드 제거")는 ADR + 유형 D 실행 제안이 된다.
4. SCR-14 ADR 없는 변경에서 [제거 지시] · [규범 편입 지시]가 각각 유형 D 제안 · 요구사항 제안을 만든다. SCR-08 항목 선택 → 지시도 같은 경로.
5. SCR-07 추적성 맵에 요구사항 → 규칙 · 계약 → 실행 연결이 그려지고 실패 · 결함 · 변이 생존이 강조되며 항목을 누르면 상세로 간다.
6. 설정의 잠정 승인 정책을 "위험도 기준"으로 바꾸면 저위험 규칙 제안이 잠정 상태로 들어가고 거절 시 유형 D 실행이 생긴다.

**범위 밖**: 작성 규칙(M6), 자유 지시(ADR-004).

### 2.6 M6 확장

**목표**: PRD M3(P2). 요구사항 역추출, 자동 모드, 실행 추적 화면, 의존성 화면, 작성 규칙, 패키징과 성능 측정.

**완료 기준 흐름**:
1. 기존 프로젝트에서 **[요구사항 자동 생성]** → 승인 대기에만 요구사항 · 규칙 · 계약 제안이 들어가고 잠정 승인되지 않는다.
2. 설정에서 자동 모드를 켜면 첫 승인 이후 [실행] 확인이 생략되지만 규범 승인은 여전히 필요하다.
3. SCR-16에 실행 카드 · 가로 스테퍼 · 단계 선택 시 수치 줄 · 이벤트 로그 · [재개]가 있고 "통과" 보고에 판정 근거 아님 표시가 붙는다.
4. SCR-13에 외부 패키지 · 사용처 · 미사용 · 영향 블록이 보인다.
5. 설정 작성 규칙에서 rule-writer 제목 지침을 바꾸고 미리보기 → [기존 규칙에 적용] → 제목 변경 제안이 승인 대기에 들어가고 진술은 바뀌지 않는다.
6. `pnpm package`가 Linux 산출물을 만들고(Windows · macOS는 needs-human), 정적 검사 · 화면 갱신 시간이 측정돼 기록된다.

**범위 밖**: 이의 제기(PRD 미결 #7), 체류 기간 상한.
