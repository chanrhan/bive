## 1. 공통

### 1.1 디자인 원칙

| 항목 | 기준 |
|---|---|
| 사용자 | 개발자(전문가) |
| 스타일 | 모던 · 간결. 정보량 최소화, 예외만 강조 |
| 참고 | **Covena AI** (주 참고), Figma, Cursor, Claude(설정 모달) |
| 테마 | 다크 모드 우선(짙은 남색 계열). 라이트 모드 후순위 |
| 아이콘 | 표준 아이콘 세트. 글자 옆 아이콘은 글자보다 약간 작게, 글자와 같은 색. 이모지 금지 |
| 문구 | 명사형 · 짧은 문구. 서술형 문장 금지. 개발 보편 용어 사용. 화면에 PRD · 화면 정의서 코드(NRM-01, P-04 등) 표기 안 함 |

### 1.2 화면 구조

```text
BIVE
├─ 프로젝트 시작
├─ 사이드바
│  ├─ 상단: 프로젝트명 · 할 일 알림 아이콘(배지)
│  ├─ 기획: 검증 · 요구사항 · 규칙 · 계약 · 추적성 맵
│  ├─ 설계: 아키텍처(L0 · L1 상세 캔버스) · 흐름도 · ERD · 의존성 · 변경 로그 · ADR
│  ├─ 실행: 실행 추적
│  └─ 하단: 오케스트레이터 연결 상태 · 설정 아이콘
├─ 중앙: 목록 + 상세 (설계 일부는 캔버스)
├─ 오른쪽: 에이전트 채팅 (고정)
├─ 할 일 (알림 아이콘으로 진입): 승인 대기 · 검토 대기열 · 계약 변경 승인 (탭)
└─ 설정 (모달): 예산 · 모델 / 잠정 승인 / 자동 모드 / 대기열 / 작성 규칙
```

- v0.4 대비: 오른쪽 근거 패널 · 하단 시트 폐지 → 필요한 정보는 중앙 상세에 포함, 오른쪽은 채팅 전용. 할 일 메뉴 → 알림 아이콘. 설정 화면 → 모달

### 1.4 공통 요소

| 요소 | 규칙 |
|---|---|
| 목록 | 검색(`/` 키로 이동) · 기준별 필터 칩(기준 안 여러 개 선택 = OR, 기준끼리 AND, 항목별 개수, 0건 비활성, 선택 시 칩에 값 표시 · ×로 해제) · [문제만] 토글(기본 꺼짐) · 필터 사용 중 결과 줄("n개 중 m개 · 초기화"). 필터 상태는 목록별 유지. 문제 항목 우선 정렬 |
| 카드 | 2줄. 1줄 = 사람이 읽는 제목, 2줄 = ID · 예외 · 시각. 정상 항목은 2줄째 예외가 비어 있음. 긴 텍스트는 말줄임 + 툴팁 |
| 상태 배지 | 판정 상태(통과 · 실패 · 미판정 · 격리 · 재검증 필요), 변이 상태(변이 검증됨 · 변이 미검증 · 변이 생존). 정상 상태(통과 · 변이 검증됨 · 변이 미검증 · 승인 · 처리됨)는 글자 없이 흐린 점, 예외만 글자 · 색 |
| 생성 주체 | 요구사항 · 규칙 · 계약마다 사람 · 에이전트 구분. 목록은 아이콘만, 상세는 이름. 에이전트 메시지는 "~ 역할명" |
| 잠정 표시 | 잠정 승인 항목 별도 표시, 준수 지표에서 분리 집계 (PRD NRM-05, JDG-03) `미정` |
| 질문 · 지시 | 항목 선택 → C 키(또는 [채팅에 참조]) → 채팅 입력에 참조 칩 → [질문] / [지시] 명시 선택 → 질문: 답변만, 규범 변경 없음 / 지시: 규범 변경 제안 + ADR → 할 일. 참조 없이는 전송 불가(항목 없는 자유 지시 불가). 규범 변경이 없는 지시는 ADR + 실행 제안 (PRD DSN-07, RUN-07) |
| 코드 열기 | 파일 · 블록 · 실패 항목에 `file:line` 링크 → IDE. 열 때 사유(화면 오류 · 정보 부족 · 디버깅) 선택 후 기록 (PRD MET-01) |
| 캔버스 | 이동 · 확대 · 맞춤. 왼쪽 위 찾기(맞는 노드 파란 테두리, 나머지 흐림, Enter · ↑↓로 이동 및 선택, Esc 해제) + 빠른 강조 칩. 노드는 숨기지 않음. 오른쪽 아래 선택 노드 정보 카드 |
| 상세 접힘 | 변경 이력 · 테스트 출력은 기본 접힘. 판정 실패면 테스트 출력 자동 펼침 |

## 2. 화면별 정의

### SCR-01 프로젝트 시작 (원본 ID: S-01)

| 항목 | 내용 |
|---|---|
| 목적 | 폴더 선택, 동기화, 초기 요구사항 생성 |
| 우선순위 (후보) | P0 폴더 열기 / P1 동기화 / P2 요구사항 자동 생성 · 근거 PRD PRJ-01~03 |
| 위치 | 최상위 "프로젝트 시작" (1.2 화면 구조) |

**구성 요소**
- **[폴더 열기]** 버튼
- **[BIVE 동기화]** 버튼 — 기존 프로젝트 (미연결)일 때 노출
- **[요구사항 자동 생성]** 버튼 — 동기화 직후(요구사항 · 규칙 · 계약 없음)의 선택지

**동작**
- **[폴더 열기]**: 프로젝트 폴더 선택. 미연결 폴더면 설정 파일 생성 (PRD PRJ-01)
- **[BIVE 동기화]**: 설계 메타 파일(블록 선언 등) 생성. 설정 파일 생성과 별개 (PRD PRJ-02)
- **[요구사항 자동 생성]**: 코드 분석 → 요구사항 · 규칙 · 계약 역추출 → 승인 대기(T-01)로 제안. 사람 승인 필수 (잠정 승인 대상 아님)

**상태**
- 기본: 문서에 정의 없음 (폴더 선택 전 화면 구성 미기술)
- 빈: **빈 폴더** → 요구사항 작성으로 이동 / **동기화 직후** → 요구사항 · 규칙 · 계약 없음 → 직접 작성 또는 **[요구사항 자동 생성]**
- 로딩: 문서에 정의 없음
- 에러: 문서에 정의 없음

**이동 경로**
- 빈 폴더 → 요구사항 작성으로 이동
- 연결된 프로젝트 (재진입): 설정 파일 감지 → 생성 · 동기화 없이 프로젝트 화면 진입
- 기존 프로젝트 (미연결): **[BIVE 동기화]** 노출
- **[요구사항 자동 생성]** → 승인 대기 (SCR-17 / T-01)

**비고**
- 사용 흐름은 기획서 5장 (새 프로젝트 · 기존 프로젝트) 참조

### SCR-02 요구사항 (원본 ID: P-01)

| 항목 | 내용 |
|---|---|
| 목적 | 요구사항 목록 · 상태 · 추적성 결함 확인 |
| 우선순위 (후보) | P0 / P1 추적성 결함 · 규칙화 불가 표시 · 근거 PRD NRM-01, NRM-06, NRM-08 |
| 위치 | 사이드바 > 기획 > 요구사항. 중앙 목록 + 상세 2단 (상세 영역 = SCR-06) |

**구성 요소**
- **카드**: 1줄 요구사항 문장 · 2줄 ID · 예외(추적성 결함 · 규칙화 불가 · 잠정 · 실패) · 시각. 생성 주체 아이콘
- **상세**: 본문, 생성 주체, 자식 규칙 · 계약(누르면 그 자리에서 진술 · 속성 · 테스트 출력 펼침), 구현 위치(자식 규칙의 대상 블록만), 변경 이력(접힘)
- **결함**: 규칙 없는 요구사항. '규칙화 불가' 표시 항목은 결함과 구분해 별도 표시 (PRD NRM-08)
- **필터**: 상태 · 작성 · 승인 · 블록

**동작**
- **[+ 새 요구사항]**: 목록 맨 위 입력 줄(⌘↵ 저장 · Esc 취소, 저장 시 규칙 제안)
- **직접 편집**
- **삭제**: 두 번 눌러 확인. 자식 규칙은 부모 없는 규칙 = 추적성 결함
- **질문 · 지시**(채팅)
- 자식 규칙 · 계약을 누르면 그 자리에서 진술 · 속성 · 테스트 출력 펼침

- 에러: 문서에 정의 없음

**이동 경로**
