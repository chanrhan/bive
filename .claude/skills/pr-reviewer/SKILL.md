# pr-reviewer

조율자는 이 스킬을 **새 서브에이전트**(모델 opus)에게 맡긴다. 검토자는 코드를 고치지 않고 판정과 지적만 돌려준다.

## 입력

- 대상: PR 번호(`chanrhan/bive#N`) 또는 문서 경로(`docs/roadmap.md`)
- 맥락: 이슈 번호와 수용 기준, 관련 PRD · SCR · ADR ID

## PR 검토 절차

1. `scripts/gh-rest.sh GET repos/chanrhan/bive/pulls/N` 과 `.../pulls/N/files`로 diff를 읽는다. 필요하면 브랜치를 체크아웃해 직접 실행한다.
2. CI: 최신 커밋의 체크가 전부 성공인지 확인한다 (`.../commits/<sha>/check-runs`). 빨강이면 그 자체로 REQUEST_CHANGES.
3. 체크리스트 (하나라도 어긋나면 REQUEST_CHANGES):
   - 이슈의 수용 기준 각 항목이 diff와 테스트로 충족되는가. PR 본문의 "수용 기준 확인" 체크가 근거와 함께 있는가
   - 범위: 이슈에 없는 변경이 섞이지 않았는가 (리팩터링 · 포맷 변경 포함)
   - 테스트: 새 동작마다 테스트가 있고, 기존 테스트를 끄거나 `skip` · `only`가 남지 않았는가
   - 문서 일치: UI 문구 · 상태 · 이동 경로가 `docs/spec/screens.md`의 해당 SCR과 맞는가. 요구사항 동작이 `docs/spec/prd.md` 수용 기준과 맞는가
   - 데이터 출처(NFR-03): 제품 코드 경로에 목 데이터 · 추정 공식 · 하드코딩 값이 없는가
   - 무결성(NFR-01 · NFR-02): 에이전트 경로에서 승인 · 규범 쓰기 · 셸 실행이 가능해지지 않았는가
   - 언어 · 표기: 한국어 문구, 명사형, 이모지 없음, 화면에 PRD · SCR 코드 노출 없음. 커밋 · 코드에 모델 이름 없음
   - 정합: 새 해석을 코드에 넣었다면 `docs/decisions.md`에 ADR이 추가됐는가
4. 정확성: 경계 조건 · 에러 경로 · 동시성(파이프, 파일 감시) 버그를 찾는다. 추측이 아니라 재현 경로를 적는다.

## 로드맵 검토 절차 (`docs/roadmap.md`)

1. `docs/roadmap-format.md` 형식 준수 여부.
2. 커버리지: `docs/spec/prd.md` 4장 · 5장의 모든 ID와 `docs/spec/screens.md`의 SCR-01~21이 커버리지 표에 있고, 각각 최소 1개 이슈 키에 연결되는가. 누락 ID를 전부 나열한다.
3. 이슈 크기: PR 하나(변경 파일 20개 이내, 서브에이전트 1회 작업)로 끝나지 않을 이슈를 지목하고 분할안을 제시한다.
4. 수용 기준: 검증 불가능한 문장("동작한다", "적절히")을 전부 지목한다.
5. 의존: 순환, 뒤 마일스톤 키에 의존하는 앞 이슈, 의존이 빠진 명백한 순서 문제를 지목한다.
6. 완료 기준 흐름이 QA가 그대로 실행할 수 있는 수준인지.

## 출력 형식

```
판정: APPROVE | REQUEST_CHANGES
요약: 한 줄
차단 지적 (고쳐야 머지):
- [파일:줄 또는 절] 무엇이 왜 문제인지, 재현 또는 근거, 제안
비차단 지적 (다음 PR 가능):
- ...
확인한 것: CI 상태, 실행한 명령
```

조율자는 차단 지적만 구현 서브에이전트에게 넘기고, 2회 반복 후에도 남으면 이슈를 쪼갠다. 비차단 지적은 이슈로 남기거나 기록한다.
