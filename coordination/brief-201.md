## 해야 할 것 (수용 기준 순서)
1. **공통 툴팁 컴포넌트.** 지금은 `title` 속성뿐이라 눌러도 동작이 없고 키보드로 닿지 않는다. 공통 컴포넌트 하나를 만든다.
   - 동작: 대상에 마우스를 올리거나 **키보드 초점**이 닿거나 **누르면** 문구가 보이고, **Esc**로 닫히며(닫힌 뒤 초점은 대상에 남는다), 초점이 떠나거나 밖을 누르면 닫힌다. 한 번에 하나만 열린다.
   - 접근성: 대상과 문구를 `aria-describedby`로 잇고 문구 요소는 `role="tooltip"`. 버튼처럼 원래 동작이 있는 대상(코드 열람)은 누름이 원래 동작을 막지 않게 한다(툴팁은 초점 · 올림으로, 누름은 원래 동작. 원래 동작이 없는 한계 문구 버튼은 누름으로 툴팁을 연다. 어느 대상이 어느 쪽인지 정해 시험으로 고정한다).
   - 문구는 화면 정의서 1.1(명사형, 이모지 없음, 코드 표기 없음)을 따르고 체크리스트(`checklists/scr-05.ts`)의 문구와 글자까지 같다(한 곳에서 가져오거나 시험이 대조).
   - 에이전트 · 판정 출력에서 온 글(카드 제목 등)을 툴팁에 실을 때는 기존 표시 값 도우미(`visibleText` · `visibleLines` · `visibleDisplayText`)를 그대로 거친다. HTML로 넣지 않는다(글자 노드로만).
   - 배치: 창 가장자리에서 잘리거나 가로 스크롤을 만들지 않는다(820 · 1100 · 1280 · 1440px). 새 의존성(툴팁 · 포지셔닝 라이브러리)을 더하지 않는다. 필요하다고 판단되면 멈추고 보고한다.
   - `e2e/scr-05.spec.ts`가 검증 화면의 "코드 열람"과 준수 카드 한계 문구 버튼에서 위 동작(초점으로 보임, 누름, Esc로 닫힘, 문구 일치)을 단언한다.
2. **카드의 잘린 제목 · 2줄 툴팁.** 공용 카드의 잘린 제목과 2줄 툴팁이 키보드 초점으로도 닿아 같은 공통 툴팁으로 보인다. `e2e/card-line.spec.ts`가 단언한다. **400px 목록의 카드 배치(카드 높이, 2줄이 각각 한 줄)가 이전과 같아야 한다**: 바꾸기 전 main에서 카드 높이 · 줄 위치를 재 두고(시험의 기존 단언이 이미 보는 값이면 그것으로) 바꾼 뒤 같은지 단언한다. 잘리지 않은 제목에는 툴팁이 뜨지 않는지(또는 뜨는지)를 화면 정의서 1.4에 따라 정하고 단언한다. 카드 자체가 이미 초점을 받는 요소(선택)이므로 탭 순서가 카드마다 두 번 멈추지 않게 한다(카드 초점에 툴팁을 묶는 쪽이 작다). 목록에 카드가 수백 개일 때 툴팁 요소 · 리스너가 카드 수만큼 늘지 않게 한다(열린 것 하나만 그린다).
3. **규칙 상세 머리의 제목 폭.** 288px 상세에서 제목이 ID · 판정 배지 · 버튼에 밀려 좁은 칸이 된다(12줄 줄바꿈). 제목 칸 폭이 상세 내용 폭의 절반 이상이 되게 배치를 고친다(예: 좁을 때 ID · 배지 · 버튼을 다른 줄로). `e2e/scr-06-rule.spec.ts`의 좁은 창 시험이 폭 비율을 단언한다. 넓은 창(1280 · 1440px)의 기존 배치가 달라지지 않는지도 단언하거나 캡처로 확인한다. PR #273이 고친 실행 이력 줄(`RuleDetail.css`의 상태 칸 줄바꿈)을 깨지 않는다.
4. **설정 IDE 섹션.** 사용자 지정 URL 틀 입력 아래에 `{path}` 값의 형태(맨 앞 `/`를 뺀 절대 경로, ADR-087)를 알려 주는 안내 문구를 둔다. 문구는 1.1 원칙(명사형, 코드 표기 금지)인데 `{path}`는 사용자가 입력란에 그대로 적어야 하는 자리 표시라 문구에 드러나야 한다. 화면 정의서 SCR-21과 ADR-087이 이 자리 표시를 화면에 어떻게 적는지 보고 같은 표기를 쓰고, 근거를 ADR-124(또는 PR 본문)에 적는다. 섹션 제목 "IDE" 아래에 같은 글자의 그룹 라벨이 또 보이지 않게 해 보이는 "IDE" 글자가 한 번이 되게 하되 **접근성 이름은 그대로** 둔다(시각적으로만 숨김. `aria-label` · `legend`의 접근성 이름을 바꾸지 않는다). `e2e/scr-21.spec.ts`가 보이는 글자 수 · 접근성 이름 · 안내 문구를 단언한다.

## 반드시 지킬 것
- 화면 데이터는 실행 · 기록 · RPC 응답에서만 만든다(NFR-03). 목 데이터는 시험 코드 안에서만. 가짜 응답은 shared 스키마를 통과해야 한다.
- 새 화면 시험에 `waitForTimeout`을 쓰지 않는다. 조건 대기와 `allSettled` · `nextFrame`을 쓴다. 올림(hover) 지연이 필요하면 CSS · 타이머에 기대지 말고 상태로 단언할 수 있게 만든다.
- 규칙마다 "빼면 빨강"인 시험을 두고 변이 결과 표를 PR 본문에 낸다(초점으로 열림, Esc 닫힘, 한 번에 하나, `aria-describedby` 연결, 표시 값 도우미, 카드 높이 유지, 제목 폭 비율, "IDE" 한 번, 접근성 이름 유지).
- 기존 `title` 속성 가운데 수용 기준이 말한 자리만 바꾼다. 나머지 `title` 자리는 목록으로 보고만 한다(후속).
- 구조 시험을 느슨하게 만들지 않는다. `docs/spec/*` · `docs/roadmap.md` · `CLAUDE.md`를 고치지 않는다.
- 바뀐 파일이 30개를 넘을 것 같으면 멈추고 보고한다. 쪼갤 경계는 "(1 · 2) 공통 툴팁과 카드" / "(3 · 4) 제목 폭과 설정".
- 완료 조건 명령: 설치 · 린트 · 타입 · 빌드 · 형식 · 단위 테스트(격리 `TMPDIR`, 알려진 두 시험만 실패 허용) · 화면 e2e · Electron 스모크. 파이프라인 e2e는 대상이 아니다(CI가 돈다).
