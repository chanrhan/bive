## 반드시 지킬 것
- 화면 데이터는 저장된 기록 · 조회 결과에서만 만든다(NFR-03). 목 데이터는 시험 코드 안에만. 시험용 가짜 응답은 shared 스키마를 지나는 것만.
- UI 문구는 `docs/spec/screens.md` 1.1(명사형, 이모지 금지, 코드 표기 금지)과 화면 정의서의 낱말 그대로('추적성 결함', '규칙화 불가').
- 응답 형식은 넓히기만 한다. 기존 `requirement.list` · `rule.list` · `verification.summary`의 기존 칸 뜻을 바꾸지 않는다. 준수 지표(ADR-117)의 분모 · 분자는 건드리지 않는다.
- 새 enum 값(승인 기록 행동 등)은 shared와 app의 표시명 표에 함께 더한다. DB CHECK에 걸리면 멈추고 보고.
- 방어 · 표시 조건마다 "빼면 빨강"인 시험과 변이 결과 표: 제외 넷 각각 빼기, 모두 폐기된 요구사항 처리 뒤집기, 빈 사유 거부 빼기(서버 · 화면 각각), 에이전트 주체 거부 빼기, 규칙화 불가를 추적성 결함으로도 보이기, 내장 규칙에 예외 보이기, 분모 0을 0%로 보이기, 카드가 필터 없이 열기, 다른 프로젝트 섞기.
- 화면 시험: `waitForTimeout` 금지, 글자 폭 · 픽셀 단언 금지, 숨은 글자는 이스케이프(역슬래시-u 표기)로. 요구사항 화면의 알림 하나에 `rule.list` 한 번(M3-42의 단언)을 깨지 않는다.
- `docs/spec/*` · `docs/roadmap.md` · `CLAUDE.md`를 고치지 않는다. 의미 있는 단위마다 로컬 커밋을 남긴다(서명 설정을 끄지 않는다).
- 이 이슈는 화면 넷에 걸쳐 크다. 바뀐 파일이 35개를 넘을 것 같거나 위 "멈추고 보고" 조건에 걸리면: 끝낸 부분까지 커밋 · 푸시하고 PR은 만들지 않은 채 남은 부분의 설계(선택지와 권고)를 보고한다(조율자가 쪼갠다).
- 완료 조건 명령: 설치 · 린트 · 타입 · 빌드 · 형식 · 단위 테스트(격리 `TMPDIR`, 알려진 두 시험만 실패 허용) · 화면 e2e(`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=$(ls -d /opt/pw-browsers/chromium-*/chrome-linux*/chrome) pnpm e2e`, `--trace off`) · Electron 스모크(`xvfb-run -a pnpm smoke`). 오케스트레이터의 IPC 처리기와 시나리오를 더하므로 픽스처 설치 뒤 `pnpm e2e:pipeline`도 PR 전에 한 번(`TMPDIR` 격리. 35분 넘게 출력이 없으면 네 프로세스만 멈추고 보고에 적는다: `ci`가 기준).
