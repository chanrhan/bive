## 사실 (구현자 보고. 네가 그 브랜치의 코드에서 확인한다)
- #319의 브랜치가 끝낸 것: 표 `run_continuations`(원 실행 ID UNIQUE: 사슬은 되고 가지는 없다) · 뷰 `run_reinforcement_causes`를 사슬을 따라가게 다시 만듦 · RPC `reviewQueue.resumeWithBudget`(사람만, `run-handlers.ts`, 실행 생성 · 연결 · 항목 처리가 트랜잭션 1개) · 새 한도의 검증(`BUDGET_SHAPE_MISMATCH` · `BUDGET_LOWERED` · `BUDGET_NOT_ABOVE_SPENT`)과 새 실행의 `budgetSnapshot` · 사슬 전체 세션을 세는 한도 계산(`lineageSessions`) · 처리 액션 `raise_limit_resume` · 보강 실행을 이은 실행의 판별과 자동 보강 막기 · 다시 예산 초과면 새 항목 · `worktree-manager.create`의 시작 커밋 입력(원 실행 브랜치의 커밋인지 git 객체로 확인).
- **그 상태에서 이어받는 실행은 원 실행의 기준 커밋에서 첫 단계부터 돈다**(원 실행이 쓴 단계의 세션을 다시 쓴다. 한도는 사슬 누적이라 새 한도 안에서). 이어받은 단계의 `skipped` 기록 · 판정 근거를 원 실행에서 읽는 것 · 회귀 카운터의 사슬 누적은 없다.
- 구현자가 남긴 중간 시작의 설계(ADR-149 "멈춘 곳"): 시작 단계 = 원 실행의 `currentStep`(예산 초과를 낸 시도의 단계. 기존 `resume`과 같은 자리)이고 그 앞 단계는 `skipped`, `exitDetail = {reason: 'inherited', fromRunId, fromStepId, fromStatus}`. 시작 커밋과 새 실행의 `headCommit` = 원 실행의 `headCommit`(없으면 기준 커밋). 회귀 카운터 = 사슬의 회귀 수 합 + 자기 회귀로 상한을 봄(테스트 작성 재시도 수는 원 실행들의 시도에서 재기동 중단 · 이어받은 시도 · 다시 하는 멈춘 시도를 뺀 수). 판정 근거 = 한 함수(`basisSteps`: 원 실행들의 단계 + 자기 단계)를 단계 실행기 6개가 씀.

## 조율자 결정 (ADR-150에 "결정"으로 적고, 행의 수용 기준에 검증 가능한 문장으로 넣는다)
1. **행 나눔**: M3-56(#319)은 "이어받는 실행 만들기 · 연결 · 새 한도의 검증과 누적 · 사람의 문과 트랜잭션 · 항목 처리 · 다시 예산 초과일 때의 새 항목 · 보강 사슬의 판별"을 맡는다. **이어받는 실행은 기준 커밋에서 첫 단계부터 돈다**(이 행까지의 동작). 새 행 M3-60이 "중간 시작"을 맡는다: 원 실행의 마지막 완료 단계 다음부터 돎, 이어받은 단계의 `skipped` 기록, 판정 근거를 연결을 거쳐 원 실행의 단계 기록에서 읽음, 원 실행의 Red 해시 보호, 재주입과 "더하기만"이 원 실행의 근거로 돎, 회귀 상한의 사슬 누적.
2. **ADR-147의 결정은 그대로다.** 달라지는 것은 순서뿐이다(② · ③의 "마지막 완료 단계 다음부터" · "이어받은 단계는 `skipped`" · "판정 근거는 원 실행의 기록에서"는 M3-60이 끝나야 성립한다). M3-56만 병합된 기간의 동작(첫 단계부터 다시 돎: 원 실행이 쓴 세션을 다시 쓰지만 한도는 사슬 누적이라 새 한도를 넘지 않는다. 무결성은 그대로다: 새 실행이 자기 단계를 실제로 돌고 자기 기록을 남긴다)을 ADR-150의 결과 절에 사실대로 적는다.
3. **중간 시작의 설계(구현자 제안을 조율자가 받아들임. 세부는 M3-60의 ADR이 정한다)**: ⓐ 시작 단계는 원 실행에서 예산 초과를 낸 시도의 단계(기존 `interrupted` 재개와 같은 자리)이고 그 앞 단계는 새 실행에 `skipped`(사유 이어받음, 원 실행의 그 단계 시도를 가리킴)로 남는다. `passed` 행을 만들지 않는다. ⓑ 새 실행의 작업 가지는 원 실행의 마지막 산출 커밋(원 실행의 `headCommit`, 없으면 기준 커밋)에서 시작한다. 원 실행의 끝나지 않은 시도가 작업 폴더에 남긴 커밋되지 않은 변경은 이어받지 않는다. ⓒ 판정 근거를 읽는 자리는 한 함수로 모으고(원 실행들의 단계 + 자기 단계) 단계 실행기들이 그것을 쓴다. 복사하지 않는다. ⓓ 회귀 상한(구현 재시도 · 테스트 작성 회귀)은 사슬 전체로 센다(이어받기로 상한을 우회하지 못한다).
4. **기대는 행**: M3-58(허용 목록 축소 재개)은 M3-56에만 기댄다(중간 시작이 없어도 성립). M3-09(화면)는 그대로 M3-56 · M3-57 · M3-58에 기댄다(M3-60은 화면이 부를 RPC를 더하지 않는다). M3 흐름 4번("원 실행의 마지막 완료 단계 다음 단계부터 이어져")은 M3-60까지 끝나야 성립한다: 목표 문단에 그렇게 적는다.
