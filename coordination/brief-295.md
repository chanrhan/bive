## 배경
테스트 작성 세션(채점 기준을 쓰는 역할)은 `test-writer/inputs.ts`가 만든 입력 사본을 받는다. 그중 둘은 **구현 역할이 만든 것**에서 나온다.
- `routes.md`: 구현 역할이 만든 라우트 폴더 이름에서 `renderRoutes`가 만든 글. 지금은 폴더 이름을 거르지 않고 싣는다(줄 나눔 글자 · 개수 · 길이 상한 없음). 폴더 이름에 줄 나눔과 문장을 넣으면 구현 역할의 글이 테스트 작성 역할의 입력에 지시문처럼 들어갈 수 있다(역할 분리 약화, ADR-100).

ADR-128이 이 둘을 "지금 처리와 남는 한계"로 적었고 이 이슈가 처리 방식을 바꾼다.

## 해야 할 것 (수용 기준 순서)
1. **라우트 경로의 안전한 조각 패턴.** `routes.md`에 실리는 경로를 조각(폴더 이름)마다 안전한 패턴으로 확인한다. 패턴은 Next.js App Router가 실제로 쓰는 폴더 이름(영숫자 · `-` · `_` · `.`, 동적 조각 `[id]` · `[...slug]` · `[[...slug]]`, 묶음 `(group)`, 병렬 `@slot`, 가로채기 `(.)` 등)을 덮되 **줄 나눔 · 제어 글자 · 공백 · 따옴표 · 백틱 · 마크다운 구조 글자**가 들어갈 수 없게 정한다. 정규식을 쓰면 선형 시간인 꼴만 쓴다(M3-01에서 정규식 폭주를 고친 적이 있다. 조각 길이 상한을 먼저 본다). 패턴 밖 조각이 하나라도 있는 경로는 **통째로 싣지 않고** 수만 고정 문장으로 알린다("싣지 않은 경로 N건" 꼴. 원문은 어디에도 싣지 않는다). 패턴과 근거를 ADR-131에 적는다. 픽스처 `fixtures/sample-next-app`의 실제 라우트가 전부 실리는지 확인한다.
2. **`routes.md`의 항목 수 · 글자 수 상한.** 항목 수 상한과 전체 글자 수 상한(경로 하나의 길이 상한 포함)을 기존 세션 입력의 상한과 같은 수준으로 정해 ADR에 적는다. 넘칠 때는 정렬된 순서로 앞에서부터 싣고 넘친 수를 머리줄에 적는다(결정적이어야 한다: 파일 시스템 나열 순서에 기대지 않는다). `test-writer.test.ts`가 경계값(상한과 같음 · 하나 넘음)으로 단언한다.
3. **`prisma/schema.prisma` 사본의 크기 상한.** 바이트 상한을 정해 ADR에 적는다. 넘칠 때의 처리를 정한다. 고를 것: (가) 사본을 만들지 않고 고정 문장으로 알린다, (나) 상한까지 잘라 싣고 잘렸음을 알린다. **기본 방침은 (가)다**(잘린 스키마는 문법이 깨진 채로 읽혀 오해를 만든다. 무엇을 싣지 않았는지는 고정 문장으로 알린다). 읽기 전에 크기를 보고(`lstat`) 상한 넘는 파일을 메모리로 올리지 않는다. 크기 확인과 읽기 사이에 파일이 바뀌는 틈도 읽은 바이트 수로 한 번 더 막는다. 사본의 **내용 처리(바이트 그대로)** 는 바꾸지 않는다: 스키마는 테스트 작성 역할이 읽어야 하는 구현 산출이고 내용을 거르면 쓸모가 없다. 이 남는 한계(구현 역할이 스키마 주석에 글을 쓸 수 있음)는 ADR에 사실대로 적는다.
4. **상위 `prisma/` 폴더가 기호 링크인 경우.** `prisma/`가 기호 링크이면(작업 공간 밖을 가리키든 안을 가리키든) 사본을 만들지 않는다. 파일 자체가 기호 링크 · 일반 파일이 아닌 경우의 기존 검사는 그대로 둔다(없으면 더한다). 라우트 나열도 같은 눈으로 본다: 라우트 폴더를 나열할 때 기호 링크 폴더를 따라가는지 확인해, 따라가면 따라가지 않게 하고 시험을 더한다(따라가지 않는 것이 이미 보장돼 있으면 그 시험만 확인해 보고에 적는다).
5. **ADR-131.** 닫은 길 · 남는 길 · 상한 값 · 근거. ADR-128의 해당 한계 문장을 "ADR-131로 닫음"으로 갱신한다(ADR-128의 다른 문장은 건드리지 않는다).

## 반드시 지킬 것
- 테스트 작성 세션에 넘기는 다른 입력(`rules/*.md` · 다른 규칙의 `*.acc.ts` · `blocks.json`)과 앞 시도 사유(`describeUnmet`)는 건드리지 않는다. 그쪽에서 결함을 찾으면 고치지 말고 보고한다.
- `prompts.ts`의 고정 문장은 입력이 빠질 수 있게 된 사실을 알리는 데 꼭 필요한 만큼만 고친다(싣지 않은 수 · 사본 없음 안내는 `routes.md` 머리줄이나 입력 사본 쪽에 두는 것이 기본).
- 기존 시나리오의 흐름과 파이프라인 e2e 기준값이 바뀌면 안 된다. 픽스처의 `routes.md` 글이 달라지면 이유를 확인하고 보고에 적는다. `pnpm -C fixtures/sample-next-app install --frozen-lockfile` 뒤 `pnpm e2e:pipeline`을 PR을 올리기 전 한 번(`TMPDIR` 격리).
- 방어마다 "빼면 빨강"인 시험을 두고 변이 결과 표를 PR 본문에 낸다(조각 패턴 확인 제거, 줄 나눔 허용, 항목 수 상한 제거, 글자 수 상한 제거, 정렬 제거, 스키마 크기 상한 제거, 읽은 바이트 재확인 제거, `prisma/` 기호 링크 검사 제거).
- 시험에서 줄 나눔 · 제어 글자가 든 폴더 이름은 이스케이프(`\n` · `\u0000` 꼴)로 쓰고 소스에 숨은 글자를 넣지 않는다.
- 악용 절차를 ADR · PR · 시험 이름에 자세히 쓰지 않는다(무엇이 어디로 들어갈 수 있는지와 막는 방법만).
- `docs/spec/*` · `docs/roadmap.md` · `CLAUDE.md`를 고치지 않는다. 의미 있는 단위마다 로컬 커밋을 남긴다(서명 설정을 끄지 않는다).
- 바뀐 파일이 12개를 넘을 것 같으면 멈추고 보고한다.
- 완료 조건 명령: 설치 · 린트 · 타입 · 빌드 · 형식 · 단위 테스트(격리 `TMPDIR`, 알려진 두 시험만 실패 허용) · 파이프라인 e2e.
