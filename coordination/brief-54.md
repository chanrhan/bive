## 해야 할 것
1. **탭과 배지** (수용 기준 3). `TODO_TABS`에 [검토 대기열]을 [확인할 것] 옆에 더한다. 배지 합계 = 확인할 것(지금 값) + 검토 대기열의 **열린** 항목 수(`reviewQueue.list`가 자르기 전 수를 주는지 확인한다. 주지 않으면 확인할 것의 `total` · `totalByKind` 선례처럼 응답에 선택 칸을 **넓히기만** 해서 더한다: 기존 칸 · 순서 그대로, shared 스키마 + 오케스트레이터 처리기 + 시험. 이것이 크면 멈추고 보고). 상한 경고 · 빨강 표시는 없다(ADR-100 D8). 툴팁의 종류별 건수에 검토 대기열 종류(변이 생존 · 예산 초과)를 기존 규칙(0건 빼고 건수 많은 순)대로 더한다. 조회 실패 · 모름일 때의 배지는 기존 규칙(NFR-03: 모르면 그리지 않는다)을 따르되, 한쪽만 실패했을 때를 정해 ADR에(권고: 합계를 모르면 배지를 그리지 않는다). 마지막 탭 기억(ADR-034: 앱 실행 동안)은 기존 방식 그대로 두 탭에 걸리게 한다.
2. **목록** (수용 기준 1 · 4). 카드 2줄: 1줄 = 대상 규칙 제목(대상 규칙이 여럿인 예산 초과 항목의 표기를 정한다: 선례가 있으면 그대로, 없으면 "첫 제목 외 n"꼴을 화면 정의서 1.5의 카드 규칙에 비춰), 2줄 = ID · 종류 · 시각. 빈 상태 "검토 항목 없음"(ADR-029). 로딩 · 에러는 1.5의 공통 상태. 필터 칩 2종: 종류(변이 생존 · 예산 초과) · 처리 상태(열림 · 처리됨. 기본값과 [초기화]는 확인할 것 탭의 선례). 처리된 항목은 어떤 액션으로 처리됐는지(표시명) 보인다. 에이전트 · 서버가 준 글은 `visibleText` 계열을 거친다. `event.reviewQueue.changed`에 다시 읽는다(기존 알림 구독 방식 그대로, 다시 읽기 폭주 방지도 선례대로).
3. **상세와 액션** (수용 기준 2). 항목을 고르면 상세(확인할 것 상세의 배치 선례): 종류, 대상 규칙(링크는 기존 규칙 링크 방식), 원인이 된 실행(표시 ID · 종료 사유 · 멈춘 단계: `reviewQueue.get`이 주는 것만 그린다. NFR-03), 변이 생존이면 살아남은 변이의 요약(주는 값만). 종류별 액션 버튼:
   - **변이 생존**: [테스트 보강](`reviewQueue.reinforce`) · [판정 격리](`reviewQueue.quarantine`: 사유 입력 필수. **사유가 비면(공백뿐 포함) 확인 버튼이 비활성**) · [이의 제기](늘 비활성: 정의 전. 비활성의 까닭을 툴팁으로. 문구는 1.1 원칙).
   - **예산 초과**: [한도 상향 재개](`reviewQueue.resumeWithBudget`: 새 한도 입력. 한도의 칸 구성은 shared 스키마와 기존 예산 설정 화면의 입력을 따른다. 지금 값 · 쓴 값을 `get`이 주면 함께 보인다) · [허용 목록 축소 재개](`reviewQueue.resumeNarrowed`: 새 한도 + 제외 경로 목록(한 줄에 하나). **안내 문구: 폴더 아래를 빼려면 끝에 `/**`를 붙인다는 뜻을 코드 표기 없이 쓰기 어렵다: 1.1의 "코드 표기 금지"는 PRD · SCR · ADR 같은 문서 기호와 내부 식별자를 말하는지 경로 패턴 예시까지 막는지 1.1 원문으로 판단해 ADR에 적는다. 막는다면 입력 칸의 자리 표시 글로 예시를 준다**) · [규칙 분할](`reviewQueue.splitRule`: 대상 규칙이 여럿이면 하나를 고른다. 누르면 분할 세션이 뒤에서 돌고 항목은 세션이 끝나 반영될 때 처리됨이 된다: 그동안의 표시(진행 중)를 `get`/`list`가 주는 값으로 그릴 수 있으면 그리고, 주지 않으면 그리지 않고 한계로 적는다. 프로세스 메모리의 잠금이라 서버가 `split_in_progress`로 거부하는 것만 보인다).
   - 액션의 거부: 서버의 거부 코드 · 고정 사유(`data.reason` · `data.fields`)를 화면 문구로 옮기는 표를 둔다(모르는 사유는 일반 실패 문구. 서버 글을 그대로 그릴 때는 `visibleText`). 입력 검증은 서버가 기준이다: 화면은 "빈 값이면 비활성" 정도만 하고 서버의 거부를 그린다(같은 규칙을 화면에 다시 구현하지 않는다. 한도 비교 · 제외 문법을 화면에서 따로 판정하지 않는다).
   - 처리 뒤: 목록 · 배지를 다시 읽고(알림이 오지만 누른 쪽은 바로), 처리된 항목의 상세는 처리 결과(액션 · 시각 · 만든 실행의 표시 ID가 있으면 그 링크)를 보인다. 처리 후 이동 화면은 명세에 없다: 그 자리에 머문다.
   - 처리된 항목 · 사람 주체가 아닌 경우의 버튼 상태. 요청이 도는 동안 버튼 중복 누름 방지(선례대로).
