## 해야 할 것
1. **`rule.get`이 최신 실행 ID · 비용 합계 · 턴을 돌려준다.** 응답에 그 규칙의 최신 실행(무엇이 "최신"인지: 그 규칙을 대상으로 한 실행 가운데 가장 나중에 만들어진 것이 기본. 규칙 상세의 실행 이력이 이미 쓰는 기준과 같게 하고 ADR에 적는다)의 ID · 표시 ID와 그 실행의 **합계 비용**(없으면 `null`) · **턴 합계**(없으면 `null`)를 넣는다. 응답 형식은 넓히기만 한다(기존 칸의 뜻을 바꾸지 않는다, 옛 클라이언트가 깨지지 않게 선택 칸이거나 기존 방식에 맞춘다).
   - **합계의 정의를 ADR-134에 정한다.** 실행의 모든 단계 시도의 모든 세션의 비용 · 턴을 더한 값이 기본이다. 이미 실행 합계를 내는 코드가 있으면 그 함수를 쓴다(같은 값을 두 가지 방식으로 계산하지 않는다).
   - **"없음"의 정의**: 세션이 하나도 없으면 `null`. 비용을 모르는 세션(값이 `null`)이 섞여 있을 때 합계를 어떻게 할지 정한다: 아는 것만 더해 보이면 실제보다 작은 값이 사실처럼 보인다(NFR-03). **기본 방침은 "하나라도 모르면 합계도 모름(`null`)"이다**(가장 보수적). 다만 기존 화면(예산 · 실행 추적 · 검증)이 이미 같은 상황을 다르게 다루고 있으면 그 선례와 ADR(#135 관련)을 확인해 맞추고, 어긋나면 근거를 적는다. 0은 "실제로 0"일 때만이다(비용 0달러인 세션이 가능한지, 가짜 에이전트의 값이 무엇인지 확인).
   - 실행이 없으면 최신 실행 자체가 `null`.
   - `orchestrator/test/rule.test.ts`가 단언한다: 실행 없음, 세션 없는 실행, 값이 모두 있는 실행(여러 단계 · 회귀로 여러 시도), 모르는 값이 섞인 실행, 여러 실행 중 최신 고르기, 다른 규칙의 실행이 섞이지 않음, 여러 규칙을 대상으로 한 실행.
2. **규칙 상세의 최신 실행 링크에 비용과 턴.** 최신 실행 링크 옆(또는 같은 줄)에 실행 합계 비용과 턴을 보인다. 값이 없으면 "없음"(0을 보이지 않는다). 비용의 표시 형식(통화 기호 · 소수 자리)은 기존 화면이 비용을 보이는 방식 그대로 쓴다(새 형식을 만들지 않는다). 최신 실행 링크가 지금 없으면 화면 정의서의 SCR-03 표시 목록대로 더하되, 링크의 이동 대상은 문서에 명시가 없으므로 기존 화면들이 실행 링크를 어디로 보내는지(실행 추적 SCR-21 등) 선례를 따르고 ADR에 적는다. 선례가 없으면 가장 보수적인 쪽(이동 없이 표시 ID만 보이기)을 고른다.
   - 문구는 1.1(명사형, 코드 표기 금지). 줄 이름은 화면 정의서 · PRD의 낱말("최신 실행", "비용", "턴")을 쓴다.
   - 다시 읽기: 실행이 끝나거나 진행되면 값이 바뀐다. 규칙 상세의 기존 다시 읽기(실행 알림)에 얹는다. 늦은 응답이 새 값을 덮지 않아야 한다(M3-35).
   - `e2e/scr-06-rule.spec.ts`가 단언한다: 값이 있으면 비용과 턴이 보임, 없으면 "없음"이고 0이 보이지 않음(비용만 모름 · 턴만 모름 · 둘 다 모름 · 실행 없음), 실제 0은 0으로 보임(가능한 값이면).
3. **ADR-134**: 최신의 기준, 합계의 정의, 모르는 값이 섞였을 때, 링크의 이동 대상, 표시 형식의 출처, 남는 한계. `docs/architecture.md`에 IPC 메서드 설명이 있으면 사실만 맞춘다.

## 반드시 지킬 것
- 값은 저장된 세션 기록에서만 만든다(NFR-03). 추정 · 환산(토큰 수로 비용을 계산 등)을 새로 만들지 않는다.
- 규칙 목록(`rule.list`) 응답과 카드는 건드리지 않는다(수용 기준은 `rule.get`과 규칙 상세다). 목록에서 N+1 조회가 생기지 않게 한다.
- `rule.get`이 느려지지 않게 한다: 최신 실행 하나의 세션만 읽는다(그 규칙의 모든 실행 · 모든 세션을 읽어 메모리에서 고르지 않는다). 쓰는 질의와 색인을 보고에 적는다.
- 방어 · 표시 조건마다 "빼면 빨강"인 시험과 변이 결과 표(모르는 값을 0으로 더하기, 모르는 값이 섞여도 아는 것만 더하기, 최신 대신 첫 실행 고르기, 다른 규칙의 실행 섞기, "없음" 대신 0 보이기, 늦은 응답이 덮기).
- 화면 시험: `waitForTimeout` 금지, 글자 폭 · 픽셀 단언 금지, 숨은 글자는 이스케이프(역슬래시-u 표기)로. 목 데이터는 시험 코드 안에만.
- `docs/spec/*` · `docs/roadmap.md` · `CLAUDE.md`를 고치지 않는다. 의미 있는 단위마다 로컬 커밋을 남긴다(서명 설정을 끄지 않는다).
