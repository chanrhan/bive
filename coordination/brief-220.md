## 해야 할 것
1. **구현 세션의 작업 지시**에 효력 있는 요구사항(표시 ID, 본문)과 규칙(표시 ID, 제목, 진술, 부모, 케이스 이름)을 M7-07과 같은 형식 · 상한으로 넣는다. 대상 규칙이 목록에서 어떻게 표시되는지(수용 기준은 "대상이 아닌 효력 있는 규칙"을 요구한다)를 정하고 ADR-108에 적는다. 프롬프트 스냅샷으로 단언한다.
2. **테스트 작성 세션**에도 같은 규범 입력을 넣는다. 세션 디렉터리의 허용 입력 사본(`test-writer/inputs.ts`)은 늘리지 않는다. 규범 입력은 작업 지시의 글로만 들어가고 파일로 복사하지 않는다. 구현 코드와 구현 세션의 글이 들어가지 않음을 단언한다.
3. **세션 기록.** 세션마다 받은 규범 입력의 표시 ID 목록(요구사항 · 규칙)과 잘림 여부 · 빠진 수를 세션 기록에 저장하고 `run.get`의 세션 항목으로 내보낸다. 지금 규칙 작성 세션의 `normInput`은 메모리에만 있다. 저장할 자리를 정한다(`sessions` 표에 칸을 더하는 마이그레이션 0017이 가장 작다. `sessions`에 UPDATE를 막는 트리거가 있는지 먼저 확인한다). 규칙 작성 세션의 `normInput`도 같은 자리에 저장할지 정하고 ADR에 적는다. 표시 ID는 화면 · CLI에 나가므로 표시 값으로 내보낸다.
4. **작업 지시 머리의 대상 본문.** ADR-106 "결과"가 M7-08에 넘긴 결정이다. 규칙 작성 · 테스트 작성 · 구현 역할의 작업 지시 머리에 요구사항 본문 · 규칙 진술이 원문 그대로 들어가는 자리를 모두 찾는다. 그 자리의 글로 틀보다 앞에 가짜 시작 · 끝 표시 줄을 만들 수 있다. 가장 보수적인 쪽은 머리의 글도 같은 표시 값 변환을 거치게 하거나, 머리에서 본문을 빼고 틀 안의 "(이번 작업 대상)" 항목만 가리키게 하는 것이다. 어느 쪽이든 정하고, 가짜 표시 줄을 넣은 요구사항으로 "출력 전체에서 줄 머리의 시작 · 끝 표시 줄이 각 1개"임을 단언하는 시험을 세 역할 모두에 둔다. 에이전트가 원문을 정확히 봐야 하는 이유가 있으면(예: 인수 테스트가 글자 그대로 비교) 그 근거를 ADR에 적고 방어 수단을 따로 둔다. 기존 시나리오 · 스냅샷이 바뀌면 PR 본문에 적는다.
5. **`norm-input` 시나리오와 파이프라인 e2e.** 요구사항 2개를 차례로 저장하는 시나리오에서 두 번째 실행의 구현 세션 규범 입력 목록에 RULE-001이 있음을 단언한다. 새 e2e 파일은 `scripts/check-pipeline-groups.py`가 보는 두 묶음 가운데 하나에 넣는다. 자동 시작(M7-05)과 실행 대기(M7-06)가 들어와 있으니 e2e 보조 `harness.saveRequirement`의 지금 동작을 먼저 읽는다.
6. **도구 목록 불변.** 두 역할의 도구 · MCP 목록이 그대로임을 `integrity.test.ts`가 단언한다. 규범은 도구가 아니라 작업 지시로만 들어온다.

## 반드시 지킬 것
- 구현 역할은 규칙 · 인수 테스트를 쓸 수 없고 테스트 작성 역할은 구현 코드를 볼 수 없다(NFR-02). 규범 입력이 이 벽을 넘는 길이 되지 않게 한다. 다른 규칙의 인수 테스트 파일 본문은 규범 입력에 넣지 않는다(A14 해석. 케이스 이름만).
- 세션 재개 · 재시도 때 규범 입력을 다시 읽는지, 처음 것을 쓰는지 정하고 ADR에 적는다(같은 실행 안 재시도의 세션 이어 가기는 M3-28이라 범위 밖이다).
- 상한을 넘겨 잘렸을 때 대상 규칙과 그 부모 요구사항이 빠지지 않음을 두 역할에서도 단언한다.
- `/confirm/i` 금지 등 `integrity.test.ts`의 구조 시험을 느슨하게 만들지 않는다. 종료 상태는 `runEnding()`만 정한다.
- `docs/spec/*` · `docs/roadmap.md` · `CLAUDE.md`를 고치지 않는다. 폐기 · 대체(M7-09), 대상 블록으로 고르기(M3-29)는 범위 밖이다.
- 검토에서 반복해서 걸린 것을 스스로 점검한다: ⓐ 보이는지만 단언하는 시험 ⓑ 방어 코드는 있는데 시험이 없는 곳(원자성, 길이 상한, 줄 나눔 글자 CR · U+2028 · U+0085 · 태그 글자) ⓒ ADR 문장이 코드와 다른 것. 숨은 글자는 시험 파일에 이스케이프 표기로만 쓴다(prettier가 `' '`을 날 글자로 바꾸니 `String.fromCodePoint(0x2028)`로 만든다).
