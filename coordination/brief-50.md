## 해야 할 것
1. **계약 화면**: 사이드바 > 기획 > 계약. 중앙 목록 + 상세 2단(요구사항 · 규칙 화면과 같은 틀과 컴포넌트를 쓴다. 새 틀을 만들지 않는다).
   - 데이터는 `contract.list`와 기존 조회(연결 규칙의 최신 판정)에서만 만든다(NFR-03). 제품 코드에 목 데이터 · 예시 값을 두지 않는다. 다리(preload · main)에 `contract.list`가 없으면 기존 읽기 전용 RPC와 같은 방식으로 더한다.
   - **카드**(1.4, 2줄): 1줄 = 사람이 읽는 제목(원본 파일 경로가 기본. 다른 화면의 선례와 문서 우선순위로 정하고 ADR에 근거), 2줄 = 표시 ID · 예외 · 시각, 생성 주체 아이콘. 예외는 결함(스키마 불일치 · 검사 규칙 없는 계약)과 확인 상태(미확인)다(ADR-100 I3).
   - **표시 / 상세**: 종류, 원본 파일, 연결 규칙(`contract` 검사 규칙의 표시 ID, 누르면 그 규칙으로 이동하는 기존 방식이 있으면 그것), 판정 상태, 생성 주체, 확인 상태. 부모 요구사항이 있으면 표시 ID. 등록 때 해시 · 커밋과 기준 브랜치와의 어긋남(`source`: `same` · `changed` · `missing` · `unreadable`)을 보일지와 문구는 문서 우선순위와 가장 보수적인 해석으로 정해 ADR에 적는다(화면 정의서의 표시 목록에 없는 값을 더할 때는 근거가 있어야 한다. 사실 값이고 NFR-03을 어기지 않지만, 넣지 않는 쪽이 범위가 작다).
   - **결함의 정의**(ADR에 적는다): "스키마 불일치" = 그 계약의 `contract` 검사 규칙의 최신 판정이 실패. "검사 규칙 없는 계약" = `contract.list`의 `rule`이 `null`. 판정 기록이 없으면 판정 없음(미판정 표기는 규칙 화면의 선례를 따른다)이고 결함이 아니다. 실행기가 아직 없어(#292 진행 중) 실제로는 지금 모든 계약이 판정 없음이다: 화면은 판정이 생기면 그대로 보이게 만들고, 시험은 e2e의 가짜 응답으로 통과 · 실패 · 판정 없음을 모두 본다.
   - **필터 칩 3종**(종류 · 검사 규칙 · 판정)과 **확인 칩**(미확인 · 확인됨), [문제만]: 값과 개수는 목록 항목에서만 센다(요구사항 · 규칙 화면의 방식 그대로). 결함이 [문제만]에 잡힌다. 미확인만으로 [문제만]에 잡히는지는 요구사항 · 규칙 화면의 M7-15 결정과 같게 한다.
   - **종류 표시명**: shared에는 값이 여섯(API · DB · 이벤트 · 외부 API · 캐시 · JSON 스키마)이고 등록되는 것은 셋이다. 표시명 표를 app에 두고(화면 정의서의 낱말 그대로) 모르는 값이 와도 깨지지 않게 한다.
   - **빈 상태** "계약 없음"(ADR-029). **로딩 · 에러**는 문서에 정의가 없다: 요구사항 · 규칙 화면과 같은 방식(ADR-073)으로 하고 ADR에 한 줄.
   - **확인 동작**: 계약의 [확인]은 만들지 않는다(확인 RPC가 계약을 받지 않고, 지금 미확인 계약이 생기는 제품 경로가 없다, ADR-129 ②). 확인 상태는 보이기만 한다. 이 판단과 근거를 ADR에 적는다. 수용 기준이 [확인] 동작을 요구한다고 읽히면 멈추고 보고한다.
   - **지시 동작**(신규 등록 지시 · 변경 지시): 화면 정의서의 "→ T-01 승인 대기 · T-03 계약 변경 승인"은 ADR-100으로 바뀌었다. 이 이슈에서 지시 입력을 새로 만들지 않는다(에이전트 채팅은 다른 마일스톤). 다른 화면이 같은 자리를 어떻게 두었는지 따르고 ADR에 적는다.
2. **체크리스트와 e2e**: `checklists/scr-04.ts`(기존 화면 체크리스트의 형식)와 `e2e/scr-04.spec.ts`. 수용 기준 3개를 그대로 단언한다: 기본 상태(종류, 원본 파일, 연결 규칙, 판정, 생성 주체, 확인 상태)와 빈 상태, 결함 2종과 미확인이 카드 2줄째 예외로 보이고 결함이 [문제만]에 잡힘, 필터 칩 3종과 확인 칩. 목 데이터는 시험 코드 안에만.
   - 화면 시험 규칙: `waitForTimeout`을 쓰지 않는다. 글자 폭에 기대는 단언(줄 바꿈 위치, 픽셀)을 쓰지 않는다(CI의 한글 글꼴 폭이 다르다). 순서 · 조건으로 단언한다. 숨은 글자는 이스케이프로 쓴다.
   - 에이전트 · 서버가 준 글(원본 파일 경로, 표시 ID)을 그릴 때 `visibleText` · `visibleDisplayText`를 거친다. 긴 경로는 공통 툴팁 컴포넌트의 기존 잘림 방식을 쓴다(`title` 속성을 새로 쓰지 않는다).
3. **ADR-133**: 위에서 정한 것(카드 제목, 결함의 정의, [문제만]과 미확인, `source` 어긋남을 보일지, [확인] 없음, 지시 동작, 로딩 · 에러, 종류 표시명)과 근거, 남는 한계. `docs/architecture.md`에 화면 목록이 있으면 사실만 맞춘다.

## 반드시 지킬 것
- 오케스트레이터 · store · shared의 동작을 바꾸지 않는 것이 기본이다. 화면에 꼭 필요한 값이 `contract.list`에 없어 응답을 넓혀야 하면 **멈추고 보고한다**(조율자가 정한다). shared에 표시용 상수만 더하는 것은 된다.
- UI 문구는 `docs/spec/screens.md` 1.1(명사형, 이모지 금지, 화면에 PRD · SCR · ADR 코드 표기 금지). 화면 정의서의 낱말을 그대로 쓴다.
- 방어 · 표시 조건마다 "빼면 빨강"인 시험을 두고 변이 결과 표를 PR 본문에 낸다(결함 판정 조건 2종, 미확인 예외, [문제만] 포함 조건, 필터 칩마다, 확인 칩, 빈 상태, 모르는 종류 값, 표시 값 변환).
- `docs/spec/*` · `docs/roadmap.md` · `CLAUDE.md`를 고치지 않는다. 의미 있는 단위마다 로컬 커밋을 남긴다(서명 설정을 끄지 않는다).
- 바뀐 파일이 25개를 넘을 것 같으면 멈추고 보고한다.
- 완료 조건 명령: 설치 · 린트 · 타입 · 빌드 · 형식 · 단위 테스트(격리 `TMPDIR`, 알려진 두 시험만 실패 허용) · 화면 e2e(`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=$(ls -d /opt/pw-browsers/chromium-*/chrome-linux*/chrome) pnpm e2e`) · Electron 스모크(`xvfb-run -a pnpm smoke`). 파이프라인 e2e는 오케스트레이터를 고치지 않았으면 돌리지 않는다.
