## 해야 할 것
1. **`verification.summary`의 두 기준**(수용 기준 1 · 2). 준수를 전체 기준(효력 있는 규칙 전체의 통과 수와 판정 가능 수)과 사람 확인 기준(확인됨 규칙만)으로 나눠 돌려주고, 두 분모의 규칙 목록이 각각 있다.
   - 효력 판정은 `norms/effective.ts`만 쓴다(`normState` 비교를 다른 파일에 쓰면 구조 시험에 걸린다). **폐기된 규칙은 두 분모에서 빠진다. 폐기된 규칙이 확인됨일 수 있다**(사람이 "폐기를 봤다"고 확인한 경우, ADR-113). 확인됨 여부만 보고 세면 폐기 규칙이 사람 확인 기준에 들어간다. 이 경우를 시험으로 단언한다.
   - 확인 상태는 확인 서비스를 거쳐 읽는다(`.confirmations` 접근은 `confirmations/confirmation-service.ts`에서만 한다는 구조 시험이 있다. 규칙 응답에 이미 `confirmation` 칸이 실려 있으면 그것을 쓴다). 요약 계산 코드가 `/confirm/i` 금지 대상 파일(엔진 · 단계 · 에이전트 · 도구 · 역할 · 판정 · 실행. `judge/`가 들어 있다)에 있는지 먼저 확인한다. 금지 대상 안이면 그 글자를 쓸 수 없으니, 확인 기준의 계산은 금지 대상 밖 모듈(검증 요약 쪽)에 둔다. 금지 목록을 느슨하게 하지 않는다. 확인 상태는 여전히 판정 · 병합의 조건이 아니다(표시용 집계일 뿐이다).
   - 확인됨 규칙이 없으면 사람 확인 기준은 `null`이다(0 / 0이 아니다). 확인됨 규칙은 있는데 판정 가능한 것이 없는 경우(전부 미판정 · 격리)의 모양도 정한다(`null`과 구분되게).
   - 기존 응답의 준수 칸을 읽는 곳(앱, CLI, 시험, 파이프라인 e2e)을 `git grep`으로 모두 찾아 새 모양에 맞춘다. 기존 칸 이름을 유지하고 사람 확인 기준을 덧붙이는 쪽이 작다.
   - 사람 확인 기준의 "확인됨"은 지금의 확인 상태다. 풀린 규칙(에이전트가 폐기 · 대체해 확인이 풀린 것)은 폐기라 어차피 빠진다. 사람이 진술을 편집해 확인됨이 된 규칙의 판정이 옛 테스트 기준일 수 있다(ADR-109 한계)는 사실을 ADR-117에 한 줄 적는다(표시는 범위 밖).
2. **에이전트가 폐기한 규칙 수**(수용 기준 4). 규범 변경 기록의 에이전트 폐기(`retired`)와 대체(`superseded`)만 센다. 요약 응답에 싣는다. 세는 단위(기록 수인지 규칙 수인지. 규칙 하나는 한 번만 폐기된다), 기간(전체 누적인지)을 정해 ADR에 적는다. `'retired'|'superseded'` 글자와 `.normChanges.` 읽기의 구조 시험 허용 목록을 넓혀야 하면 이유를 PR 본문에 적는다(읽기만 한다. 쓰기는 여전히 `agent-rule.ts`만이다). 폐기 기록 접근(`ruleRetirements`)은 효력 모듈에서만 한다는 구조 시험이 있다. 폐기 수를 폐기 행에서 셀지 규범 변경 기록에서 셀지 정한다(수용 기준은 규범 변경 기록이라고 적었다. 두 원천이 어긋나면 어느 쪽을 믿는지).
3. **SCR-05 검증 화면**(수용 기준 3 · 4).
   - 준수 카드에 두 기준이 함께 보인다. 사람 확인 기준이 `null`이면 '없음'으로 보인다('0 / 0' 금지). 사람 확인 기준을 누르면 SCR-03이 `준수 집계: 판정 가능` + `확인: 확인됨` 필터로 열린다. 전체 기준을 누르면 지금처럼 열린다. 열린 SCR-03의 카드 수가 검증 화면의 분모와 같아야 한다(SCR-03의 "사람 확인" 칩 정의 = 판정 가능 ∩ 확인됨, `rules/rulesView.ts`의 `complianceValues`. 네 분모 정의와 어긋나면 한쪽을 맞추고 그 사실을 ADR에 적는다).
   - 에이전트가 폐기한 규칙 수가 보이고, 누르면 SCR-03이 [폐기 포함] 필터(`FilterState.includeHidden`)로 열린다. 0이면 어떻게 보이는지 정한다(화면 정의서의 카드 규칙을 따른다).
   - 검증 화면의 규칙 제목이 원문 렌더링이다(`VerificationScreen.tsx`의 `row.rule.title`). 에이전트가 쓴 글이므로 `visibleText`(`components/VisibleText/visibleText.ts`)로 그린다. 이 화면에서 에이전트 글이 그려지는 다른 자리도 훑는다.
   - 문구: 명사형, 이모지 금지, 화면에 코드 표기 금지. 두 기준의 이름을 화면 정의서 · ADR-100의 낱말로 정하고 PR 본문에 적는다.
   - e2e: `e2e/scr-05.spec.ts`가 두 기준의 값 · 배치, '없음' 표시, 누른 뒤 SCR-03의 필터 상태와 남는 카드 수, 폐기 수와 [폐기 포함]으로 열림을 단언한다. "보인다"만이 아니라 값과 이동 결과를 단언한다. 창 폭 820 · 1280에서 준수 카드가 깨지지 않음을 본다. 가짜 요약(`e2e/checklists/scr-05.ts`)을 새 모양에 맞추고, 그 가짜 데이터를 함께 쓰는 다른 spec이 깨지지 않게 전체 화면 e2e를 한 번 돌린다.
