## 해야 할 것
1. **도구 들이기.** `@redocly/cli` · `@stoplight/prism-cli`를 오케스트레이터 패키지의 의존성으로 **정확한 판 고정**으로 더한다(실측 판 `@redocly/cli@2.77.0` · `@stoplight/prism-cli@5.16.0`이 기준. 다른 판을 고르면 근거를 ADR에). 설치 스크립트 허용 목록(`pnpm.onlyBuiltDependencies`)은 **바꾸지 않는다**. 설치 스크립트가 필요하거나 설치 때 외부 실행 파일을 받는 것이 보이면 **멈추고 보고한다**(사람 결정 #287과 같은 종류다). 잠금 파일은 pnpm으로만 갱신한다.
2. **OpenAPI 계약 검사 실행기**(`contract-runner`): 등록된 OpenAPI 계약 하나에 대해 (a) `@redocly/cli lint`로 문서 유효성을, (b) 판정 서버 앞 `@stoplight/prism-cli proxy --errors`로 구현 응답이 계약과 맞는지를 본다(ADR-033). 판정 결과는 `pass` · `fail`과 사람이 읽을 케이스 요약(표시 값 변환 · 상한은 구조 검사 판정 기록의 방식).
   - 계약 파일은 **판정 커밋의 git 객체 또는 깨끗한 체크아웃**에서 읽는다(작업 트리 아님. M3-04가 정한 읽기 함수를 그대로 쓴다).
   - **도구가 대상 프로젝트의 코드를 실행하지 않게 한다.** 실측: `@redocly/cli`는 cwd가 프로젝트 안이면 `redocly.yaml`의 플러그인 JS를 실행한다. cwd를 프로젝트 밖의 빈 임시 폴더로 두고 계약 파일 사본만 넘기거나 BIVE가 가진 설정을 명시해 막는다. prism도 같은 눈으로 확인한다(설정 파일 · 플러그인을 찾는 경로).
   - **네트워크로 나가지 않게 한다.** 문서의 원격 `$ref`(http · https · 파일 밖 경로)를 받아 오지 않는다. 도구에 끄는 선택 항목이 없으면 도구를 부르기 전에 문서를 읽어 계약 파일 밖을 가리키는 `$ref`가 있으면 닫힌 쪽(`fail` 또는 판정 불가. ADR에 정함)으로 끝낸다. 사용 기록 전송은 `REDOCLY_TELEMETRY=off` 등으로 끈다. 자식 프로세스의 환경 변수는 허용 목록만 넘긴다(파서 자식 프로세스 방식, ADR-125). **프록시 환경 변수를 넘기지 않는다. 프록시 값을 설정 파일에 옮겨 적지 않는다. 프록시 환경 변수의 값을 출력하지 않는다.**
   - 도구의 오류 · 시간 초과 · 출력 초과 · 예상 밖 종료 코드가 `pass`로 읽히지 않는다(닫힌 쪽). 종료 코드만 믿지 않고 출력 형식도 확인한다. 중단 신호가 자식 프로세스까지 이어진다. prism 프록시 포트는 임의 빈 포트를 쓰고 끝나면 반드시 정리한다(실패 · 중단 경로 포함).
3. **검사 단계 연결.** 검사 단계(와 병합 재검사, 구조 검사가 끼어 있는 같은 자리)가 판정 대상 규칙 중 검사 종류 `contract`인 규칙을 그 규칙이 가리키는 계약의 **종류별 실행기**로 판정해 판정 기록을 남긴다. 실행기가 없는 종류(Prisma · AsyncAPI)의 규칙은 **판정 없음**으로 남고 통과로 세지 않으며, 그 때문에 다른 규칙의 실행이 막히지 않는다(ADR-130 ⑤. M3-04가 남긴 지금 동작을 깨지 않는지 시험으로 고정한다). 계약 판정이 `fail`일 때의 흐름(구현 회귀, 회귀 상한)은 구조 검사 실패와 같은 방식이 기본이다. 다르게 해야 하면 근거를 ADR에.
   - `judgments.runner`에 새 값이 필요하면 마이그레이션 `project/0025_…`로 표를 다시 만든다(0023의 색인 · 트리거 복원 목록을 그대로 따르고 `store/test/migrate.test.ts`에 옛 행 보존 시험). 새 실행 종료 사유를 더하면 shared의 `RunFailureReason`과 app의 표시명 표에 함께 더한다.
   - **실행 유형(B · C · D)의 단계 구성과 유형 B가 받는 규칙은 M3-06(#51) 몫이다. 건드리지 않는다.** 내장 구조 규칙의 `run.create` 거부도 그대로 둔다.
4. **판정 러너의 프록시 자리.** 판정 러너에 "판정 서버 앞에 프록시를 끼우는" 자리를 **선택 옵션**으로 더한다. 옵션이 없으면 판정 동작이 한 글자도 달라지지 않음을 `orchestrator/test/judge-runner.test.ts`가 단언한다(기존 시험을 고치지 않고 더한다).
5. **픽스처와 변형.** `fixtures/sample-next-app`에 `openapi.yaml`을 더하고(픽스처의 실제 API 라우트와 맞는 최소 문서), `scripts/make-variant.sh`에 `contract-mismatch` 변형(응답 필드 타입 위반)을 더한다. `orchestrator/test/contract-runner.test.ts`가 변형에서 `fail`, 원본에서 `pass`를 단언한다. 픽스처가 바뀌면 파이프라인 e2e의 기준값 · 파일 대조 · 묶음 나누기(`.github/workflows`)에 닿는지 먼저 확인하고, 닿으면 필요한 만큼만 고쳐 PR 본문에 적는다.
6. **격리 시험(대조군).** `parser/test/isolation.test.ts` 방식으로: (a) 프로젝트에 `redocly.yaml`과 플러그인 JS(실행되면 표식 파일을 남김)를 두고 실행기를 돌려 표식이 **없음**을, 방어를 뺀 대조군에서는 표식이 **있음**을 단언한다. (b) 문서에 `127.0.0.1`의 로컬 시험 서버를 가리키는 원격 `$ref`를 두고 실행기를 돌려 서버가 요청을 **받지 않음**을, 대조군에서는 **받음**을 단언한다. 대조군이 성립하지 않으면(도구가 원래 안 나가면) 그 사실을 실측으로 ADR에 적고 시험은 "나가지 않음"만 단언한다.
7. **ADR-132.** 도구 판과 실측(패키지 수, 설치 스크립트 없음, 설정 실행 · 원격 참조 · 사용 기록의 막는 방법), 실행기의 판정 규칙(무엇이 `fail`인가), 닫힌 쪽 목록, 판정 기록의 모양, 남는 한계. `docs/architecture.md`에 검사 단계 설명이 있으면 사실만 맞춘다.

## 반드시 지킬 것
- 판정 격리를 우회하는 길을 만들지 않는다. 실제 API 키를 쓰지 않는다. 이 VM은 프록시 환경이라 외부로 나가는 설치 · 내려받기가 느리거나 막힐 수 있다: 설치가 세 번 다르게 시도해도 안 되면 멈추고 보고한다.
- 방어마다 "빼면 빨강"인 시험과 변이 결과 표(cwd 격리 제거, 원격 `$ref` 사전 검사 제거, 환경 변수 허용 목록 제거, 도구 오류를 통과로 읽기, 종료 코드만 믿기, 실행기 없는 종류를 통과로 세기, 실행기 없는 종류가 실행을 막기, 프록시 옵션이 기본으로 켜짐, 프록시 정리 누락).
- 기존 시나리오의 흐름과 파이프라인 e2e 기준값이 바뀌면 이유를 확인하고 보고에 적는다. `pnpm -C fixtures/sample-next-app install --frozen-lockfile` 뒤 `pnpm e2e:pipeline`을 PR을 올리기 전 한 번(`TMPDIR` 격리).
- 화면 문구를 더하면 `docs/spec/screens.md` 1.1을 지킨다(명사형, 코드 표기 금지). 화면 파일을 고치면 화면 e2e와 Electron 스모크도 돌린다.
- `docs/spec/*` · `docs/roadmap.md` · `CLAUDE.md`를 고치지 않는다. 의미 있는 단위마다 로컬 커밋을 남긴다(서명 설정을 끄지 않는다).
- **크기 관리.** 이 이슈는 크다. 다음 순서로 커밋을 쌓는다: ① 도구 들이기와 실측, ② redocly 실행기와 격리 시험, ③ 검사 단계 연결과 "실행기 없는 종류" 고정, ④ 판정 러너 프록시 옵션, ⑤ prism 실행기와 픽스처 변형. ③까지 끝난 시점에 바뀐 파일(잠금 파일 제외)이 25개를 넘거나 ④ · ⑤가 판정 러너의 큰 구조 변경을 요구하면 **멈추고 보고한다**(조율자가 이슈를 쪼갠다. 그때까지의 커밋은 브랜치에 남긴다).
- 완료 조건 명령: 설치 · 린트 · 타입 · 빌드 · 형식 · 단위 테스트(격리 `TMPDIR`, 알려진 두 시험만 실패 허용) · 파이프라인 e2e.
