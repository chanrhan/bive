## 사실 (구현자 보고. 네가 코드에서 확인한다)
- `budget_exceeded`는 바뀌지 않는 종료 상태다: 프로젝트 마이그레이션 0016의 트리거 `runs_terminal_final` · `steps_run_terminal_insert` · `steps_final`, shared `RUN_STATUS_TRANSITIONS.budget_exceeded = []` · `TERMINAL_RUN_STATUSES`, `RunRepository.transition`의 종료 상태 거부. 대기열 깨우기(ADR-105)와 자동 보강의 "끝나지 않은 보강 실행" 판단도 이 전제를 쓴다.
- 실행의 한도는 `budget_snapshot`에 박히고 `runs_identity_immutable`이 변경을 막는다.
- 구현 역할의 파일 허용 목록은 없다: `orchestrator/src/tools/path-guard.ts`에는 금지 경로와 테스트 작성 역할의 `writableRuleDirs`만 있다.
- 대체 도구 `supersede_rule`은 규칙 1개를 1개로만 대체한다.
- `run.resume`은 `interrupted`만 받는다(`ipc/run-handlers.ts`).
- #53의 브랜치가 끝낸 것: 표 `review_items`(종류 `budget_exceeded` · `mutant_survived`, 열린 항목은 실행마다 하나, 처리는 한 번) · 사람 보강 연결 표, 종료 저장과 같은 문장에서의 자동 등록, RPC `reviewQueue.list` · `get` · `reinforce` · `quarantine`, 알림 `event.reviewQueue.changed`. **예산 초과 항목은 등록되지만 처리 액션이 없어 열림으로 남는다.** 보강 실행이 `budget_exceeded`로 끝나면 예산 초과 항목 하나만 생기고 변이 생존 항목은 보강 실행이 `failed`로 끝났을 때만 생긴다.

## 조율자 결정 (ADR-147에 "결정"으로 적고, 새 행의 수용 기준에 검증 가능한 문장으로 넣는다. 세부 모양은 각 구현 이슈의 ADR이 정한다)
1. **종료 상태는 그대로 둔다.** `budget_exceeded` 실행을 `running`으로 되돌리지 않는다. 0016의 트리거 · 전이 표 · 저장소의 거부를 풀지 않는다. 근거: 종료 상태 불변은 기록 무결성(NFR-01)의 전제이고 여러 판단(대기열 깨우기 · 자동 보강의 중복 확인)이 기대고 있다. PRD TODO-02는 "한도 상향 재개"라고만 적고 같은 실행 행을 되살리라고 하지 않는다. CLAUDE.md 2장의 "가장 보수적인 해석(무결성을 더 지키는 쪽)"이다.
2. **재개 = 이어받는 새 실행.** 사람의 재개 액션은 원 실행과 같은 유형 · 대상 규칙 · 기준 커밋을 가진 새 실행을 만들고, 원 실행과 잇는 연결을 저장한다(새 표). 새 실행은 원 실행이 끝낸 단계의 산출(작업 가지의 커밋: 테스트 작성 커밋 등)을 이어받아 **원 실행의 마지막 완료 단계 다음 단계부터** 돈다. 이어받은 단계는 새 실행에서 다시 돌지 않고, 이어받았다는 사실과 원 실행의 어느 단계인지가 기록에 남는다. 원 실행 하나에 끝나지 않은 이어받는 실행은 많아야 하나다.
3. **새 한도 = 새 실행의 한도.** 새 한도는 새 실행을 만들 때의 예산 값으로 들어간다(`runs_identity_immutable`을 풀지 않는다. 설정은 바뀌지 않는다). 새 한도가 원 실행이 쓴 양보다 크지 않으면 `-32001`. 이어받는 실행의 사용량은 원 실행이 쓴 양을 이어 센다(한도는 원 실행부터의 누적 기준).
4. **사람의 문을 그대로 지난다.** 시작 주체는 사람이고, 설정 확인 · 프로젝트당 실행 1개(대기) 등 사람의 `run.create`가 지나는 문을 그대로 지난다. 하루 한도와의 관계는 사람의 `run.create`가 하는 대로다(구현 이슈가 코드를 보고 ADR에 적는다).
5. **허용 목록 축소**는 실행마다의 선택 값이다. 값이 없으면 지금 동작 그대로다(모든 실행의 기본 동작을 바꾸지 않는다). 이 액션으로 만든 이어받는 실행에만 값이 붙고, 구현 세션의 쓰기가 그 목록으로 좁혀진다. 사람에게 보이는 처음 목록은 대상 블록의 include이고 사람은 빼기만 한다(더하는 값은 `-32001`). 뺀 경로의 쓰기는 경로 가드가 거부한다.
6. **검토 항목의 처리**: 이어받는 실행이 만들어지면 그 예산 초과 항목은 처리됨이다(실행 생성 · 연결 · 처리는 트랜잭션 1개). 이어받는 실행이 다시 `budget_exceeded`로 끝나면 M3-08의 자동 등록이 그 실행의 새 항목을 만든다(새 규칙 없음).
7. **규칙 분할**은 따로 행으로 둔다(M3-57). 사람의 액션이 규칙 작성 역할 세션을 띄우고, 그 세션이 대상 규칙을 2개 이상으로 대체한다(쓰기 트랜잭션 1개, 사유와 근거, 승인 대기 제안 없음: ADR-100). 지금 대체 도구는 1 → 1이므로 1 → 여럿을 한 트랜잭션으로 하는 길(도구 확장 또는 새 도구)을 그 이슈가 정한다. 원 실행은 `budget_exceeded`로 남는다. 세션이 2개 미만으로 끝내면 항목은 열림 그대로다. 새 규칙의 실행은 기존 자동 시작이 맡는다.
8. **행 나눔의 근거**: M3-56(이어받는 실행 · 한도 상향 재개 · 허용 목록 축소 재개)은 엔진 · 저장 · 경로 가드를, M3-57(규칙 분할)은 규칙 작성 역할과 대체 도구를 고친다. 겹치는 파일이 적고 각각이 이슈 1개 크기다.
